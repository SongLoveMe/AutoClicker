# AutoClicker

基于 C++17 和 Qt Widgets 的 Windows 自动点击工具。

![版本](https://img.shields.io/badge/version-2.3.0-blue)
![语言](https://img.shields.io/badge/language-C%2B%2B17-orange)
![Qt](https://img.shields.io/badge/Qt-6.5.3-green)

当前以 2.3 为开发基线，整理界面与交互。版本号保持 `2.3.0`，本轮没有生成新的正式安装包。

## 界面与操作

- **顶部执行区**：显示版本、状态、开始、暂停／继续和停止按钮。
- **左侧设置区**：点击参数、随机化、目标窗口和原生控件定位；窗口较小时可滚动。
- **右侧点位区**：手动坐标、录制和点位表格，展示序号、按键、X、Y、点击后间隔及绑定窗口。
- **状态提示**：显示点位数量、已执行次数、启动条件和错误原因。

### 手动创建序列

1. 输入屏幕 X、Y，点击“添加点位”。手动点位沿用左键、绝对坐标。
2. 重复添加其他点位；双击表格行修改屏幕坐标。
3. 选择行后，可删除、上下移动；右键对应行可设置独立间隔，`0` 表示使用全局间隔。
4. 设置执行次数：正数为指定次数，`-1` 为无限，`0` 不执行。
5. 检查点击方法，点击“开始”或按 F6。

执行次数统计引擎执行次数；一次双击／三击动作会发送多次鼠标按下，但计为一次执行。序列的每个点位计为一次执行，并非整个序列计一次。

### 录制序列

1. 点击“开始录制”，在目标应用中点击；左、右、中键及点位窗口绑定会被记录。
2. 点击“停止录制”，检查表格中的点位和间隔。
3. 设置非零执行次数后开始执行。

录制与执行互斥。执行或暂停期间，参数和点位编辑均锁定；编辑对话框打开时，F6 不会启动执行。

### 窗口和元素

- 录制点位使用各自记录的窗口绑定，左侧窗口选择不会重新绑定已有点位。
- 原生控件定位需要先刷新窗口列表、选择目标窗口，再输入文字并查找。
- 定位成功后，元素点击优先于序列；修改搜索文字或切换窗口可取消定位。
- 刷新列表会保留仍存在的选中窗口；切换窗口或取消元素定位后，下次启动会清除引擎中的旧元素。
- 跟随鼠标模式目前没有 UI 入口；空点位且没有有效元素时禁止启动，避免点击默认原点。

### 点击方法与热键

| 项目 | 行为 |
| --- | --- |
| 无干扰 | 使用窗口消息；目标应用是否接受消息需实际验证，部分回退路径可能移动鼠标。 |
| 模拟鼠标 | 使用 SendInput，移动鼠标并发送点击，会影响当前鼠标操作。 |
| F6 | 开始／停止；同样遵守界面的启动条件。 |
| F7 | 暂停／继续。 |

F6/F7 沿用全局低级键盘钩子实现；UAC、安全桌面及权限隔离场景不作保证。窗口置顶沿用 2.3 的行为。

## 验证状态

### 已验证

- 使用指定 Qt 6.5.3、Qt MinGW 13.1.0、Ninja 进行 Debug 构建。
- 点位表格的新增、坐标编辑、删除、排序、序号更新和选中项保留。

- 通过替换输入适配器的临时检查，验证 F6/F7 回调、自动完成恢复，以及切换目标后不再沿用旧元素。
- 100%、125%、150% Qt 缩放下的临时布局边界检查。

隔离验证不向其他应用发送真实鼠标点击；它不能代替目标应用的兼容性验证。临时测试代码与可执行文件在验证结束后清理，不保留在项目中。

- 无干扰点击、后台／最小化窗口、管理员权限窗口和具体游戏的兼容性。

### 已知限制与后续修复清单

本轮保持 2.3 核心引擎不变，以下审查发现的问题尚未修复：

1. 暂停后继续、停止后快速重启，旧计时回调可能影响新执行，产生提前或额外点击。
2. 双击／三击执行中停止，剩余子点击仍可能发出。
3. 窗口外框、客户区及还原位置坐标混用；绑定窗口、最大化窗口和模拟鼠标可能出现位置偏移。
4. 无标题窗口关闭等情况下，窗口失效判断可能漏检；窗口身份匹配也不够严格。
5. 无干扰长按先松开再等待，长按语义不正确；部分路径会回退为模拟鼠标。
6. 无干扰双击消息序列不正确，可能影响目标控件状态。
7. 录制间隔保存与回放使用的时机错位，原始节奏不能准确复现。
8. 模拟鼠标按主屏尺寸映射坐标，副屏及负坐标不能正确覆盖；手动输入范围仍为 0～9999。
9. 配置管理尚未接入主界面的保存／恢复；关闭程序不会保存当前点位和参数。

## 构建

仅面向 Windows，使用 C++17、Qt 6.5.3、Qt MinGW 13.1.0 和 Ninja；不使用 MSYS2 MinGW。

```powershell
$env:PATH = "D:\Qt\Tools\mingw1310_64\bin;D:\Qt\6.5.3\mingw_64\bin;D:\Qt\Tools\CMake_64\bin;D:\Qt\Tools\Ninja;$env:PATH"

cmake -S . -B build -G Ninja `
  -DCMAKE_BUILD_TYPE=Debug `
  -DCMAKE_PREFIX_PATH=D:/Qt/6.5.3/mingw_64 `
  -DCMAKE_C_COMPILER=D:/Qt/Tools/mingw1310_64/bin/gcc.exe `
  -DCMAKE_CXX_COMPILER=D:/Qt/Tools/mingw1310_64/bin/g++.exe
cmake --build build
windeployqt --compiler-runtime --no-translations build/AutoClicker.exe
.\build\AutoClicker.exe
```

日常开发使用 `build/`，发布使用 `build-release/`，不按版本号建立构建目录。当前没有注册 CTest 测试，零测试不能记作验证通过。每项功能／修复分别进行 code review，全部完成后再做整体 review；按风险临时验证并清理测试产物。

## 发布

正式发布前同步更新 CMake 版本、README 徽章和更新日志。`CMakeLists.txt` 的项目版本是程序、安装包和发布文件名的唯一版本来源。

安装 Inno Setup 6 后运行：

```powershell
.\scripts\package.ps1
# 自定义安装器路径：
.\scripts\package.ps1 -InnoSetupPath "D:\Tools\Inno Setup 6\ISCC.exe"
```

输出为 `release/AutoClicker-Setup-x.y.z.exe` 及 SHA-256 文件。正式发布前需验证安装、启动、升级和卸载，以及文档中宣称支持的目标应用。
